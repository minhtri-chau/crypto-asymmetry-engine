# v8.9.4 deployment

v8.9.4 replaces the ambiguous single Amount / Entry Price workflow with a transaction-based purchase ledger.

## 1. Run the Supabase migration

Run the **v8.9.4 position transaction ledger** block at the bottom of `supabase.sql` in the Supabase SQL Editor. It creates `public.position_transactions`, its index, RLS policies, authenticated CRUD grants, and adds position-context columns to `signal_observations` for later signal/outcome analysis.

## 2. Deploy frontend

Push the v8.9.4 files to GitHub `main` and let Vercel deploy.

No Edge Function redeploy, Cron change, environment-variable change, or dependency change is required.

## Smoke test with the existing AAVE position

1. Open AAVE Research.
2. The **Your position** panel should detect the old `3.11 AAVE @ $160` plan values and offer **Import into ledger**.
3. Click Import, confirm the purchase date, then click **Save Purchase**.
4. Confirm AAVE shows:
   - Tokens held: 3.11
   - Average cost: $160
   - Total cost basis: $497.60
   - Current value from live AAVE price
   - Unrealized P/L in dollars and percent
5. Add a second small test purchase at a different price. Confirm weighted average cost, total tokens and P/L recalculate.
6. Delete the test purchase. Confirm the position recalculates.
7. Confirm the first saved purchase automatically marks the asset owned and updates the legacy plan/research ownership fields for compatibility with Portfolio and existing monitoring.
8. Confirm the Promotion Review section builds with `</button>)}` and never `</button>})}`.

Sales / realized P&L are deliberately not invented in this release. v8.9.4 models purchase lots and unrealized position economics; the schema can be extended for sell transactions later.
