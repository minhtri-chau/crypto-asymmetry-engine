# v8.9.6 deployment: Signal Outcome Engine

v8.9.6 adds forward validation for the existing Signal Journal. It measures what happened after recorded Entry and Position signals instead of assuming the rules work.

## What it measures
For each matured Signal Journal observation at 7D, 30D and 90D:
- asset forward return
- BTC forward return
- asset return minus BTC return
- maximum favorable excursion (MFE)
- maximum adverse excursion (MAE)
- maximum peak-to-trough drawdown inside the forward window
- observed daily-price sample count

Model provenance is stored as `outcome-v1`.

The results are observational. v8.9.6 does **not** retune setup-v3, Thesis Strength, Entry Signal or Position Signal thresholds.

## 1. Run the database migration
Run `V8.9.6-MIGRATION.sql` in Supabase SQL Editor.

## 2. Deploy the new Edge Function
Deploy:

`supabase/functions/signal-outcomes/index.ts`

Function name: `signal-outcomes`

JWT verification must be OFF. The included `supabase/config.toml` contains:

```toml
[functions.signal-outcomes]
verify_jwt = false
```

The function reuses existing Edge Function secrets:
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `MONITOR_CRON_SECRET`
- `COINGECKO_DEMO_API_KEY`

## 3. Install the daily cron
Run `supabase/signal-outcomes-cron.sql` in Supabase SQL Editor.

It runs at 00:45 UTC daily, after the existing research evaluation jobs.

## 4. Manual backfill / smoke test
After the migration and function deployment, run:

```sql
select net.http_post(
  url := (select decrypted_secret from vault.decrypted_secrets where name='project_url')
         || '/functions/v1/signal-outcomes',
  headers := jsonb_build_object(
    'Content-Type','application/json',
    'x-monitor-secret',
    (select decrypted_secret from vault.decrypted_secrets where name='monitor_cron_secret')
  ),
  body := '{}'::jsonb,
  timeout_milliseconds := 30000
);
```

A successful response looks like:

`{"ok":true,"observations":...,"pending":...,"inserted":...,"assets":...,"outcomeVersion":"outcome-v1"}`

Then open **Validation** in the dashboard.

## Important semantics
- A 7D result is not written until the full 7-day horizon has matured. Same for 30D and 90D.
- The worker backfills existing Signal Journal observations within CoinGecko Demo's practical 365-day history window.
- Signal Journal observations are the source of truth. The current app journals Entry/Position observations for researched assets; it does not fabricate historical scanner rows that were never stored.
- Small samples must not be treated as proof. Positive-rate is descriptive, not a forecast probability.
- No automatic score/threshold optimization occurs in v8.9.6.
