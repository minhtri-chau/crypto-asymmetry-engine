# v8.9.7 patch: server-side daily signal capture

This is a patch release intended to be applied on top of the **current GitHub main**. It deliberately contains only new/additive files so it does not overwrite the post-v8.9.6 pagination and Supabase-key fixes already made directly in main.

## Why
Until now, `signal_observations` was primarily written when a Research detail page was opened. That creates click/sampling bias. v8.9.7 records one observation per non-archived researched asset every day on the server, whether or not the dashboard is opened.

## Semantics
The worker reproduces the current Entry/Position decision gates using:
- latest daily `research_evaluations`
- current automated Thesis Strength / Coverage
- CoinGecko 365D price history for price pattern / RSI / extension
- the same broad Market Regime inputs
- saved plan risk/profit thresholds
- transaction-ledger position context
- the same structural invariant: a fresh cross with zero completed weekly closes above resistance is `BREAKOUT ATTEMPT`; `RETEST / HOLD` requires at least one completed weekly close above.

It writes provenance:
- `capture_source = server_daily`
- `signal_model_version = decision-v8.9.6`

It does not change setup-v3, thesis scoring, Entry/Position thresholds, or Outcome Engine math.

## Deploy
1. Run `V8.9.7-MIGRATION.sql`.
2. Create/deploy Edge Function named `daily-signal-capture` from `supabase/functions/daily-signal-capture/index.ts`.
3. Set Verify JWT OFF. If using repo config, merge the contents of `supabase/config-v8.9.7-snippet.toml` into the existing `supabase/config.toml`.
4. Run `supabase/daily-signal-capture-cron.sql`.

The cron runs at 00:35 UTC, after `research-monitor` at 00:30 and before `signal-outcomes` at 00:45.

## Manual smoke test
```sql
select net.http_post(
  url := (select decrypted_secret from vault.decrypted_secrets where name='project_url')
         || '/functions/v1/daily-signal-capture',
  headers := jsonb_build_object(
    'Content-Type','application/json',
    'x-monitor-secret',
    (select decrypted_secret from vault.decrypted_secrets where name='monitor_cron_secret')
  ),
  body := '{}'::jsonb,
  timeout_milliseconds := 30000
);
```

Expected shape:
`{"ok":true,"captured":...,"skipped":...,"regimeScore":...,"captureSource":"server_daily","signalModelVersion":"decision-v8.9.6"}`

Then verify:
```sql
select observed_date, signal_mode, signal_label, capture_source, signal_model_version, count(*)
from public.signal_observations
where observed_date = current_date
group by 1,2,3,4,5
order by 1 desc,2,3;
```

## Important
This improves data collection **going forward**. It does not invent missing historical daily signals. Existing historical observations remain unchanged.
