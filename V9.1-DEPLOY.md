# Crypto Asymmetry Engine v9.1 — Automated Qualitative Intelligence

v9.1 fills the largest evidence gap exposed by v9.0: the AI analyst can reason over numbers, but current catalysts, token-holder value capture, tokenomics/unlocks, competitive changes and protocol risks require fresh sourced evidence.

## Architecture
Quant engine remains unchanged.
Sourced Qualitative Intelligence uses the OpenAI Responses API with web search and strict structured output.
The latest sourced record is then included in the existing AI Research Engine packet.
Nothing in v9.1 changes Setup Evidence, Thesis Strength, Entry/Position thresholds, monitoring rules or trades.

## Files
- `api/qualitative-research.js` new authenticated/allow-listed server endpoint.
- `V9.1-MIGRATION.sql` new private per-user evidence table.
- `patches/FRONTEND-PATCH.txt` current-main surgical UI integration.
- `patches/AI-RESEARCH-PATCH.txt` connects qualitative evidence into v9 AI analysis.
- `vercel.json` preserves v9.0 60-second duration and adds it to qualitative research.

## Security/cost safeguards
The new endpoint reuses `AI_ALLOWED_EMAILS`.
Missing allow-list means no access.
Valid Supabase login is required.
Request body is capped at 20,000 characters.
Output is capped at 7,000 tokens.
The endpoint does not expose `OPENAI_API_KEY`.
Web search has a separate API tool-call cost, so sourced research is manual/on-demand in v9.1 rather than automatically run every day.

## Apply
1. Apply to CURRENT GitHub main, not an old ZIP.
2. Add `api/qualitative-research.js`.
3. Replace/merge `vercel.json` with the included version.
4. Run `V9.1-MIGRATION.sql` in Supabase SQL Editor, then append it to repo `supabase.sql`.
5. Apply `patches/FRONTEND-PATCH.txt` surgically to current `src/main.jsx`.
6. Apply `patches/AI-RESEARCH-PATCH.txt` to current `api/ai-research.js`.
7. Redeploy Production. Existing `OPENAI_API_KEY` and `AI_ALLOWED_EMAILS` are reused. No new secret is required.

## Recommended workflow
For a researched asset:
1. Run/refresh Sourced qualitative intelligence.
2. Review the cited evidence.
3. Run/refresh AI Research.
The AI Research Engine then receives both deterministic evidence and the latest sourced qualitative record.

## Smoke test
Run sourced research on AAVE.
Expected:
- `/api/qualitative-research` returns 200.
- UI shows catalyst/value-capture/dilution/risk states and clickable sources.
- `public.qualitative_research` receives a row.
- Refresh AI Research and verify its analysis discusses sourced token value capture/catalysts rather than saying those fields are simply missing.

SQL:
select ra.symbol,q.observed_at,q.model,q.catalyst_state,q.value_capture_state,q.dilution_state,q.risk_state,q.summary
from public.qualitative_research q
join public.research_assets ra on ra.id=q.research_asset_id
order by q.observed_at desc
limit 20;
