# v9.1.1 qualitative JSON/transport hotfix

This hotfix is based on current GitHub main after the user's v9.1 security/link changes.

## Root issue
The UI unconditionally called `response.json()`. Vercel/platform errors can be plain text or HTML, so a failed function request was masking the real HTTP failure with:
`Unexpected token ... is not valid JSON`.

The server also unconditionally parsed the OpenAI response as JSON, creating the same failure mode one layer upstream.

## Fix
1. Server reads OpenAI response as text first, parses JSON defensively, and always returns controlled JSON errors.
2. Browser reads the Vercel response as text first, parses JSON defensively, and shows the real HTTP/error message.
3. Model stays `gpt-5.6-sol`; official OpenAI docs currently list it as a Responses API model with Web search support.
4. Existing auth, AI_ALLOWED_EMAILS, request caps, output cap, 60-second Vercel duration, and HTTPS-only source-link safeguard remain unchanged.
5. No DB migration, score change, signal change, or structure change.

## Apply
- Replace current `api/qualitative-research.js` with the included file.
- Apply `patches/FRONTEND-HOTFIX.txt` to the current `runQualitativeResearch()` only.
- Redeploy Production.
- Run AAVE sourced research again.

If it still fails, the UI will now expose the actual status/detail instead of a JSON parse error. That will distinguish an OpenAI error from a Vercel timeout/platform error.
