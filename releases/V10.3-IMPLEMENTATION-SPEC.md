# v10.3 Price Expectation Validation

Implement a new Supabase Edge Function `price-expectation-validation`. Reuse CURRENT main's v10.2 functions verbatim for:
`vec`, `S`, `dist`, `wq`, `periods`, `pconf`, K=40 and weights `1/(0.15+distance)^2`.

For every historical replay observation used as a test anchor, recreate what v10.2 would have known ON THAT DATE.

For each 7/30/90D horizon:
1. Actual = anchor's matured historical_replay_outcome.
2. Candidate neighbors must have observation_date < anchor date.
3. CRITICAL leakage gate: candidate observation_date + horizon <= anchor date.
4. Rank by the exact v10.2 distance and keep nearest 40.
5. Compute exact v10.2 weighted q25 / median / q75 and weighted median BTC-relative outcome.
6. Compute v10.2 confidence from candidate n, non-overlapping periods, median distance and IQR.
7. Build an unconditional baseline using ONLY same-asset outcomes that had matured by the anchor date.
8. Zero-return baseline is 0%.

Aggregate asset-specific validation:
- sample_count
- independent_count (non-overlapping anchor dates for that horizon)
- range_coverage_pct = actual return inside predicted q25..q75
- central_mae_pct = median abs(weighted median prediction - actual)
- central_bias_pct = median(prediction - actual)
- directional_agreement_pct = sign(weighted median) == sign(actual)
- btc_relative_mae_pct
- zero_baseline_mae_pct = median abs(actual)
- unconditional_baseline_mae_pct = median abs(leakage-safe unconditional median - actual)
- improvement percentages vs both baselines
- separate LOW and MODERATE confidence summaries

Also produce cross_asset rows for REPORTING ONLY. Never feed them into asset expectations or decisions. Warn that crypto assets are correlated and pooled sample_count is not independent trials.

Validation state:
- INSUFFICIENT if sample_count <30 OR independent_count <8
- PROMISING only if evidence floor passes AND central MAE beats BOTH baselines by >=5% AND q25-q75 coverage is 40-65% AND directional agreement >=55%
- otherwise WEAK

PROMISING is only a research-validation label. It changes nothing in v10.3.

Upsert on:
`user_id,scope,research_asset_id,horizon_days,validation_version`
using the NULLS NOT DISTINCT unique index.

Return diagnostics and errors per asset. No OpenAI, CoinGecko or Vercel API function is required.
