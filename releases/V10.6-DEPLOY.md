# v10.6 — Refresh Research for any coin

Adds **Research → open a coin → Refresh Research**. It runs only that coin's quantitative evaluation, sourced qualitative research, catalyst/unlock event ingestion, and independent AI assessment, in order. Each step shows progress. A failed step keeps completed records and skips dependent steps; retry using the same button after resolving the error. Stay on the page while the run completes. Repeated refreshes create new assessment/evaluation history and make paid AI requests.

## Apply the code

This zip contains actual replacement/new code files, tests, and these instructions. Extract into the root of your existing v10.5 checkout, preserving paths. No SQL migration is needed.

1. In **Supabase → Edge Functions → research-monitor → Code**, replace `index.ts` with the complete contents of `supabase/functions/research-monitor/index.ts` from this release and deploy it. Keep JWT verification disabled as configured in `supabase/config.toml`; this worker authenticates with `x-monitor-secret`.
2. In Vercel, confirm the server environment variable `MONITOR_CRON_SECRET` matches the secret already configured in Supabase. It must not have a `VITE_` prefix. Existing `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `OPENAI_API_KEY`, and `AI_ALLOWED_EMAILS` settings still apply. Your sign-in email must be on the AI allowlist for sourced research and AI assessment.
3. Commit and push all release changes from your local branch as usual. Wait for Vercel to show Ready. If you changed Vercel environment variables, redeploy so they take effect.
4. Open **Research → Lido DAO → Refresh Research**. It resolves the coin's asset ID automatically; no SQL query, function payload, or code edit is needed for later coins.

The API checks that the deployed worker supports single-asset targeting before sending any POST. An older worker yields a redeploy message and is never invoked as a full scan by this button. Scheduled POSTs with an empty body or `{}` still evaluate the research universe.

## What changes and what remains incomplete

The quantitative worker updates `research_assets.thesis_strength`, `thesis_coverage`, `thesis_components`, and `thesis_updated_at`, and inserts a `research_evaluations` row. The remaining steps store evidence in `qualitative_research`, `catalyst_events`/`catalyst_event_runs`, and `ai_research_assessments`. The AI receives the newly saved quantitative and sourced research plus newly loaded event records. The detail page reads the refreshed asset rather than keeping the asset object captured when it was opened.

Existing score semantics remain intact. Qualitative/AI output is independent of the deterministic thesis and Setup scores; this release does not assign new score weights or copy unsourced text into thesis fields. Missing fundamentals or qualitative evidence can still leave coverage partial. The sourced research and event panels show the collected evidence even when legacy thesis-text fields remain empty.

No new cron jobs, tables, or SQL edits. Price history onboarding and downstream outcome/calibration workers keep their existing schedules.

Production LDO research is not run as part of preparing this release. After deployment, use the button and verify all four steps show Complete. If an upstream service times out or the AI allowlist rejects the request, the corresponding step displays its error and retains earlier work.
