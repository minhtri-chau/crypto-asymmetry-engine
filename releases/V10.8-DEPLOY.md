1. Run `releases/V10.8-MIGRATION.sql` in Supabase SQL Editor BEFORE deploying the frontend. It creates the private adoption_evidence_snapshots table with RLS and authenticated permissions. It is also appended to supabase.sql; do not rerun all historical SQL unnecessarily.

3. No Supabase function redeployment, cron change, new API route, dependency or secret is needed. Existing CoinGecko Demo key is reused. There are still 11 API functions.
4. Research → open a coin → Refresh Research without AI, or use Refresh adoption data without AI on its panel.

## Behavior and limits
The without-AI workflow attempts quantitative evaluation AND direct data, even if either fails. It never calls OpenAI. With-AI workflow also collects direct data before its existing three AI stages; keep using without AI while credits are exhausted.

DefiLlama metrics use exact CoinGecko-ID mapping to a unique protocol family. Historical TVL, trailing 30-day fees and trailing 30-day protocol revenue are collected when supported. Unsupported/ambiguous mappings remain unknown. This adapter does not invent chain or token economics, net deposits, users or developer retention. Public GitHub commit history comes from one CoinGecko-listed repository and is explicitly an activity proxy with a 28-day measurement window; it is not a count of core developers. A repository list does not establish whole-project coverage.

Daily provider rows must cover every day in the aggregate window; gaps are not zeros. Current unfinished UTC day is excluded. Provider errors, GitHub 202 pending responses and rate limits remain missing with diagnostics. Source dates and stale-data handling remain visible. Provider calls are bounded by timeouts and cached; a public source can still fail and require retry.

Snapshots are saved once per user/asset/UTC collection day. Older successful snapshots remain available across browsers and outages. Up to 210 daily snapshots are loaded to retain 180-day comparison history. Direct and previously saved AI observations are merged, with comparable definitions required for growth. Failed/no-data collection does not overwrite a saved snapshot. No paid AI call is made when merely loading saved records.

Collection is on demand through these buttons, not a new background cron. Direct collection has no OpenAI token charge; public data providers still have usage limits. Existing scores, thresholds, price expectations, AI safeguards, events, positions and monitoring are unchanged.
