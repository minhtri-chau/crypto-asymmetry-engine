# v9.3.1 Multi-Year History

## Goal
Backfill years of real daily Coinbase Exchange candles into the v9.3 provenance table, then let replay/calibration use that history. No paid subscription is required for the Coinbase path.

## Deploy
1. Run `V9.3.1-MIGRATION.sql` and append it to CURRENT `supabase.sql`.
2. Add `supabase/functions/multi-year-history/index.ts`.
3. Merge config snippet into CURRENT `supabase/config.toml`.
4. Deploy `multi-year-history` with JWT verification OFF.
5. Verify and persist Coinbase product mappings using `VERIFIED-MAPPING.md`.
6. Dry run:
```sql
select net.http_post(
 url := (select decrypted_secret from vault.decrypted_secrets where name='project_url') || '/functions/v1/multi-year-history',
 headers := jsonb_build_object('Content-Type','application/json','x-monitor-secret',(select decrypted_secret from vault.decrypted_secrets where name='monitor_cron_secret')),
 body := '{"years":5,"dry_run":true}'::jsonb,timeout_milliseconds:=30000);
```
7. Inspect function logs/report. Only VERIFIED_READY mappings should proceed.
8. Import with `{"years":5}`.
9. Apply `patches/HISTORICAL-REPLAY-PATCH.md` to CURRENT historical-replay worker and deploy it.
10. Run historical replay with a 5-year requested lookback, then run evidence-calibration again.

## Verification
```sql
select ra.symbol,h.source,count(*) days,min(h.price_date) first_day,max(h.price_date) last_day
from public.historical_price_daily h join public.research_assets ra on ra.id=h.research_asset_id
group by ra.symbol,h.source order by days desc;
```
