# v9.3.2 Dynamic History Onboarding

## Result
No hardcoded ten-coin SQL mapping list is required for future Research assets.

When a coin enters Research:
1. the app saves the research asset;
2. `/api/history-onboard` verifies the signed-in user owns that row;
3. the server calls `research-history-onboard`;
4. the canonical `multi-year-history` worker resolves the asset against Coinbase's live active USD products;
5. a unique verified product is persisted;
6. five years of available Coinbase candles are imported automatically.

Ambiguous or unavailable mappings are recorded, never guessed.

## Deploy
1. Run `V9.3.2-MIGRATION.sql` and append to CURRENT `supabase.sql`.
2. Replace CURRENT `supabase/functions/multi-year-history/index.ts` with included version.
3. Add `supabase/functions/research-history-onboard/index.ts`.
4. Merge config snippet into CURRENT `supabase/config.toml`.
5. Deploy/redeploy both Edge Functions with JWT verification OFF.
6. Copy `api-history-onboard.js` to repo path `api/history-onboard.js`.
7. Add Vercel Production env `MONITOR_CRON_SECRET` with the SAME value already stored in Supabase Vault as `monitor_cron_secret`. This secret remains server-side. Do not prefix it with VITE_.
8. Apply `patches/FRONTEND-PATCH.md` surgically to CURRENT `src/main.jsx`.
9. Redeploy Vercel.

## Existing assets
Run `multi-year-history` once after deployment. It dynamically resolves all non-archived Research assets that do not already have mappings. Existing verified mappings are revalidated, not replaced.

## Smoke test
Promote a new Coinbase asset from Scanner to Research. Do not run mapping SQL.
Then check:
```sql
select symbol,coingecko_id,coinbase_product_id,history_mapping_status,history_mapping_note,history_verified_at
from public.research_assets
where stage<>'archived'
order by id desc;
```
A uniquely resolvable Coinbase USD asset should become VERIFIED and populate `coinbase_product_id`.

Then:
```sql
select ra.symbol,count(*) days,min(h.price_date),max(h.price_date)
from public.historical_price_daily h
join public.research_assets ra on ra.id=h.research_asset_id
group by ra.symbol
order by days desc;
```

## Important
Research onboarding does not wait for history import. A failed/ambiguous history mapping cannot block Research. The normal scheduled replay/calibration cycle can consume the history after it arrives.
