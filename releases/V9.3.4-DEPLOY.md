# v9.3.4 Incremental History Sync

Built from current GitHub main after v9.3.3.

## What changes
- First sync for an asset: full 5-year backfill, unchanged.
- Later nightly syncs: query the newest persisted Coinbase `price_date`, then request only the last 3 days plus newer candles.
- The 3-day overlap intentionally refreshes recent daily candles.
- Existing verified Coinbase mappings are revalidated every 30 days instead of every night.
- Unmapped/failed assets are still retried by the self-healing nightly scan.
- `force_full:true` remains available for repair/backfill.
- Current CoinGecko-vs-Coinbase identity verification is preserved.

## Deploy
1. Replace CURRENT `supabase/functions/multi-year-history/index.ts` with the included file.
2. Deploy `multi-year-history`. JWT verification remains OFF as already configured.
3. No SQL/schema migration and no cron change are required. Keep the v9.3.3 nightly self-healing cron.
4. Manually invoke once with the normal body `{"years":5}`.
5. Inspect Edge Function response/log. Existing assets should report `sync_mode:"INCREMENTAL"`; a brand-new asset with no stored history should report `FULL_BACKFILL`.

## Repair mode
To deliberately rebuild five years for all active Research assets:
`{"years":5,"force_full":true}`

Do not use repair mode in the nightly cron.

## Expected scaling effect
A normal existing asset changes from roughly 8 Coinbase candle windows for a 5-year refetch to one small overlapping window. Runtime/API load therefore scales much more gently as Research grows.
