# v9.6 Decision & Expectation Engine

## Goal
Turn the existing research stack into one practical, auditable posture without pretending to forecast an exact future price.

Inputs:
deterministic Entry/Position signal + Thesis/Setup + market structure/regime + sourced qualitative research + AI stance + multi-year calibration + v9.5 live outcomes.

Outputs:
ENTRY: RESEARCH NEEDED / WAIT / ENTRY WATCH / ENTRY SETUP
POSITION: HOLD / HOLD-ADD WATCH / REASSESS-HOLD / REDUCE-PROFIT REVIEW / EXIT REVIEW
plus 7D/30D/90D empirical expectation context.

## Important
The server worker intentionally does NOT alter `decisionSignal`. Hard risk/profit and coverage gates remain authoritative. Historical and AI evidence can make the displayed posture more cautious, but cannot bypass missing research or a hard risk trigger.

## Deploy
1. Run `V9.6-MIGRATION.sql`, append to `supabase.sql`.
2. Add `supabase/functions/decision-expectation/index.ts`.
3. Merge config snippet into `supabase/config.toml`; deploy function with JWT OFF.
4. Run `supabase/V9.6-CRON.sql` once.
5. Apply frontend patch to CURRENT main.
6. Apply AI patch to CURRENT `api/ai-research.js`.
7. Redeploy Vercel.
No new Vercel API route is added.

```sql
from public.decision_expectations d
join public.research_assets ra on ra.id=d.research_asset_id
order by d.observed_at desc limit 30;
```

## Recommended smoke test
AAVE should show a practical posture plus separate 7D/30D/90D empirical context. Given the currently observed v9.4 AI state was MIXED with CAUTIONARY historical evidence, v9.6 must not silently relabel that evidence as bullish. Exact posture depends on the current deterministic signal and ownership state at run time.

## v9.6 is not auto-calibration
No production thresholds are tuned from replay or outcomes. That remains a later evidence-gated step after enough live samples mature.
