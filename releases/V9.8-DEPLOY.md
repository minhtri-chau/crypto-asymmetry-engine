# v9.8 Decision Scorecard
Purpose: measure what actually happened after stored final decision postures.

No backfill. Never reconstruct old decision postures from historical replay. Only real `decision_expectations` recorded by v9.6+ qualify.

Deploy migration, then add two JWT-OFF Supabase functions: `decision-outcomes` and `decision-scorecard`. Schedule outcomes before scorecard. Add the scorecard UI to Validation. No Vercel API route is needed.

UI filters: 7/30/90D, ENTRY/POSITION, all-assets/selected-asset. Rows are postures. Columns: n, asset count, median return, q25/q75, median BTC-relative, positive rate, BTC outperformance rate, MFE, MAE, max drawdown, confidence.

Rules: horizons separate; ENTRY/POSITION separate; asset/cross-asset separate; positive rate is descriptive not probability; no “best/worst/winner/accuracy”; insufficient stays insufficient. Do not change production thresholds from v9.8 results.

Also make v9.7 similarity observational only. Its ~48% AAVE walk-forward diagnostic is not decision evidence, so remove its ability to downgrade ENTRY SETUP.

BTC benchmark must use the already-fixed v9.5 approach: saved BTC-USD history if available, Coinbase fallback otherwise.
