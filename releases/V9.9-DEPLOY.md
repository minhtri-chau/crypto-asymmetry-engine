# v9.9 Calibration Lab

## Why this version
v9.8 has zero matured outcomes today. Automatically tuning thresholds now would be statistical theater. v9.9 therefore builds the governance layer that tells us WHEN there is enough independent forward evidence to review a production rule.

## What it audits
30D outcomes for:
1. Entry Setup Evidence
2. Entry Thesis Strength
3. Position Regime Score

Daily decisions are de-overlapped per asset into non-overlapping 30D observations before readiness is assessed.

Initial readiness floor:
- >=10 independent 30D observations
- across >=4 assets

This is only a REVIEW floor, not proof. v9.9 emits no numeric threshold recommendation and changes no decision rule.

## Deployment
1. Run V9.9-MIGRATION.sql and append to current supabase.sql.
2. Deploy `calibration-lab` with Verify JWT OFF.
3. Merge config snippet.
4. Schedule it 02:55 UTC after decision-scorecard.
5. Apply frontend patch to CURRENT main.
6. Optional AI packet patch.
7. No Vercel API route is added.

## Manual run
Use the same pg_net pattern as the other workers, endpoint `/functions/v1/calibration-lab`.

## Release blockers
- No production threshold mutation.
- No numeric threshold proposal in v9.9.
- Readiness uses independent 30D observations, not raw daily count.
- Entry and Position remain separate.
- Asset count is required in addition to independent n.
- Missing/immature outcomes never become neutral or positive evidence.
- Existing v9.8 Decision Scorecard remains unchanged.
- v9.7 similarity remains observational only and cannot alter posture.
- Hard stop/profit rules remain authoritative.
